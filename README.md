# MeetingMind 🧠

> **Agentic Meeting Intelligence with Persistent Knowledge Graphs**
> Built for the LangChain × SurrealDB Hackathon (March 2026)

MeetingMind transforms meeting transcripts into a queryable knowledge graph, enabling natural language questions about people, teams, actions, and decisions across your entire meeting history.

## What It Does

**Problem**: Organizations lose critical context from meetings. Information gets siloed in notes, decisions are forgotten, and tracking who's working on what becomes impossible at scale.

**Solution**: MeetingMind uses LangGraph agents to extract structured entities and relationships from meeting transcripts, stores them in SurrealDB as a persistent graph, and translates natural language questions into SurrealQL graph queries for intelligent retrieval.

### Key Features

- **Automated Knowledge Graph Construction** - Extracts people, teams, topics, and actions from raw transcripts using GPT-4o-mini with structured outputs
- **Natural Language Querying** - Ask questions like "Who is working on the recommendation engine?" and get accurate answers by translating queries to SurrealQL
- **Graph-Native Storage** - Uses SurrealDB's native graph traversal (`->` and `<-` syntax) for relationship queries without JOINs
- **Interactive Visualization** - D3.js force-directed graph with real-time updates showing the knowledge network
- **Two LangGraph Flows**:
  1. **Ingest Pipeline**: NodeExtractor → EdgeExtractor → GraphWriter
  2. **Query Pipeline**: AgenticSearch → SurrealQueryExecutor → InferAnswer

## Architecture

### Backend: LangGraph + SurrealDB

Two autonomous agent workflows orchestrate all logic:

**1. Ingest Flow** (`POST /process-notes`)
```
Meeting Transcript
    ↓
NodeExtractor (GPT-4o-mini)
    → Extracts: Person, Team, Topic, Action
    ↓
EdgeExtractor (GPT-4o-mini)
    → Extracts: assigned_to, work_for, helps_to_achieve, blocked_by, reports_to
    ↓
GraphWriter
    → Writes to SurrealDB using native graph schema
```

**2. Query Flow** (`POST /query`)
```
Natural Language Question
    ↓
AgenticSearch (GPT-4o-mini)
    → Translates to SurrealQL using prompt_03.yaml
    → Example: "Who is working on X?" → SELECT *, ->assigned_to->action.* AS actions FROM person WHERE...
    ↓
SurrealQueryExecutor
    → Executes graph traversal query against SurrealDB
    ↓
InferAnswer (GPT-4o-mini)
    → Synthesizes natural language answer from graph results
```

### SurrealDB Schema

**Node Tables**: `person`, `team`, `topic`, `action`
**Edge Tables**: `assigned_to`, `work_for`, `helps_to_achieve`, `blocked_by`, `reports_to`

All queries use **SurrealDB's native graph traversal syntax**:
- `->edge_table->target_table.*` (outbound traversal)
- `<-edge_table<-source_table.*` (inbound traversal)

Example real query generated by the system:
```sql
SELECT *, ->assigned_to->action->helps_to_achieve->topic.* AS topics
FROM person
WHERE name = 'Tariq Salim';
```

### Frontend: React + D3

- **Ingest Panel**: Upload transcripts, process with animated progress
- **Chat Panel**: Natural language query interface with citations
- **Graph Visualization**: D3 force-directed layout showing entities and relationships
- **Status Bar**: Live metrics (meetings, people, actions)

# - SURREALDB_USER=admin

## How SurrealDB is Used

MeetingMind leverages **SurrealDB's graph capabilities** as the core storage and query layer:

### 1. Graph-Native Schema
- Nodes stored as records in typed tables (`person`, `team`, `topic`, `action`)
- Relationships stored as edge records (`assigned_to`, `work_for`, etc.)
- Schema enforces semantic meaning (e.g., `assigned_to` only connects `person` → `action`)

### 2. Natural Language → SurrealQL Translation
The `AgenticSearch` node uses a carefully engineered prompt ([prompt_03.yaml](backend/app/graph/prompts/prompt_03.yaml)) to teach GPT-4o-mini how to:
- Map English questions to graph traversals
- Use SurrealDB's `->` and `<-` syntax for relationship following
- Apply filters with `WHERE` clauses
- Avoid unsupported SQL features (no JOINs, no aggregate functions)

**Example translations**:
- "Who works on team X?" → `SELECT *, ->work_for->team.* AS teams FROM person WHERE array::len(->work_for->team) > 0;`
- "What is Clara working on?" → `SELECT *, ->assigned_to->action.* AS actions FROM person WHERE name = 'Clara Whitfield';`

### 3. Graph Traversal for Multi-Hop Queries
SurrealQL's native syntax enables complex relationship chains:
```sql
-- "Which topics are people working on?" (2-hop traversal)
SELECT *, ->assigned_to->action->helps_to_achieve->topic.* AS topics FROM person;
```

### 4. Real-Time Graph Retrieval
The `/graph` endpoint fetches the entire graph structure for D3 visualization using a single query that retrieves all nodes and edges with their relationships intact.

## How LangChain/LangGraph is Used

### LangGraph Orchestration

Two **StateGraph** workflows handle all business logic:

**1. ProcessNotes Graph** ([flow.py](backend/app/graph/flow.py))
- **State Management**: `NotesRequest` tracks transcript text, extracted entities, edges, and status
- **Nodes**: 3 agent nodes (NodeExtractor, EdgeExtractor, GraphWriter)
- **Flow**: Linear pipeline with state passing between nodes
- **Error Handling**: Each node validates and enriches state before passing to next

**2. Query Graph** ([flow.py](backend/app/graph/flow.py))
- **State Management**: `QueryRequest` tracks user question, generated SQL, graph results, and final answer
- **Nodes**: 3 agent nodes (AgenticSearch, SurrealQueryExecutor, InferAnswer)
- **Flow**: Linear pipeline transforming NL question → SurrealQL → results → answer

### LangChain Components

- **ChatOpenAI**: All LLM calls use GPT-4o-mini with structured outputs (Pydantic models)
- **ChatPromptTemplate**: YAML-based prompts loaded dynamically ([prompts/](backend/app/graph/prompts/))
- **BaseAgent Pattern**: Each node inherits from a base class that handles LLM initialization and prompt loading
- **Pydantic Structured Outputs**: Entity extraction uses `.with_structured_output()` for type-safe parsing

### Why This Architecture?

- **Modularity**: Each agent node is independently testable and swappable
- **Observability**: LangSmith tracing captures the full flow (optional)
- **Scalability**: Stateless nodes enable horizontal scaling
- **Maintainability**: Prompts are version-controlled YAML files, not hardcoded strings

## Example Workflows

### 1. Ingest a Meeting

**Input**: "Meeting 5 — Product Roadmap Planning..."

**LangGraph Flow**:
1. **NodeExtractor** extracts:
   - Person: Clara Whitfield (VP Product)
   - Person: Marcus Lin (Lead Engineer)
   - Team: Product Team
   - Action: Ship recommendation engine MVP
   - Topic: Q2 Product Roadmap

2. **EdgeExtractor** extracts:
   - Clara Whitfield `assigned_to` Ship recommendation engine MVP
   - Marcus Lin `work_for` Product Team
   - Ship recommendation engine MVP `helps_to_achieve` Q2 Product Roadmap

3. **GraphWriter** writes to SurrealDB:
   ```sql
   CREATE person:clara_whitfield CONTENT {...};
   CREATE team:product_team CONTENT {...};
   RELATE person:clara_whitfield->assigned_to->action:ship_recommendation_engine_mvp;
   ```

### 2. Query the Graph

**User Question**: "What is Clara Whitfield working on?"

**LangGraph Flow**:
1. **AgenticSearch** generates SurrealQL:
   ```sql
   SELECT *, ->assigned_to->action.* AS assigned_actions
   FROM person
   WHERE name = 'Clara Whitfield';
   ```

2. **SurrealQueryExecutor** runs query, returns:
   ```json
   [
     {
       "id": "person:clara_whitfield",
       "name": "Clara Whitfield",
       "assigned_actions": [
         {"name": "Ship recommendation engine MVP", "description": "..."}
       ]
     }
   ]
   ```

3. **InferAnswer** synthesizes:
   > "Clara Whitfield is responsible for shipping the recommendation engine MVP. This action contributes to the Q2 Product Roadmap."
